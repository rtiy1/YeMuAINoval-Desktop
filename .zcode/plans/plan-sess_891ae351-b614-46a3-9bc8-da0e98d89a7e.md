# 助手栏模型图标路由 + 思考强度差异化

## 决策摘要
- **图标**：用 `@lobehub/icons` 显示模型真实品牌图标（Claude/OpenAI/Gemini/Grok…）
- **思考强度**：不支持思考的模型 → 选择器**显示但禁用（灰色）**
- **模型列表**：后端从 8 个同步更新到 **11 个**，与 MCODE 包 `ALL_MODEL_CONFIGS` 对齐

## 能力矩阵依据（基于 MCODE 源码，不联网）
依据 `packages/mcode/src/utils/thinking.ts` 的 `modelSupportsThinking()` 逻辑：
- 1P/Foundry：所有 4+ 模型支持（含 Haiku 4.5），`claude-3-*` 不支持
- 3P（Bedrock/Vertex）：仅 `sonnet-4`/`opus-4` 支持
- adaptive thinking（无 budget）：仅 `opus-4-6`/`sonnet-4-6`

依据 `effort.ts`：仅 `opus-4-6`/`sonnet-4-6` 支持 effort

## 实现步骤

### 1. 后端 `apps/backend/src/mcode/providers.ts`
- `ProviderModel` 接口添加 `capabilities` 字段：
  ```ts
  capabilities?: {
    thinking: boolean;
    thinkingLevels: string[];  // 支持的级别 id
    adaptiveThinking?: boolean;
    effort?: boolean;
  }
  ```
- `MODELS` 数组从 8 个扩展到 11 个（新增 haiku45/sonnet45/sonnet46/opus41/opus45/opus46），移除旧别名条目或保留，按上表填 `capabilities`

### 2. 后端 `apps/backend/src/routes/providers.ts`
- `/api/models` 返回值添加 `capabilities` 字段透传

### 3. 前端 `apps/frontend/src/lib/api.ts`
- `ModelInfo` 接口添加 `capabilities` 字段（同后端结构）

### 4. 安装 `@lobehub/icons`
```bash
cd apps/frontend && npm install @lobehub/icons
```

### 5. 前端新建 `apps/frontend/src/components/ModelIcon.tsx`
图标路由组件，按模型 ID 子串匹配品牌：
```tsx
import { Claude, OpenAI, Gemini, Grok, DeepSeek, Qwen, Cpu } from '@lobehub/icons';

// 匹配规则（顺序敏感）：
// includes('claude') || includes('sonnet') || includes('opus') || includes('haiku') → <Claude size={14} />
// includes('gpt') || includes('openai') → <OpenAI size={14} />
// includes('gemini') → <Gemini size={14} />
// includes('grok') → <Grok size={14} />
// includes('deepseek') → <DeepSeek size={14} />
// includes('qwen') → <Qwen size={14} />
// fallback → <Cpu size={14} />
```
用 Mono（单色）变体适配深色主题，size={14} 与现有 lucide 图标一致。

### 6. 前端 `AssistantPanel.tsx` — ModelSelector
- 用 `ModelIcon modelId={selectedModel}` 替换 `<Cpu size={14} />`
- 下拉列表项前也加 `ModelIcon`（每个模型项显示其品牌图标）
- `onSelect` 时把选中模型的 capabilities 一并传出

### 7. 前端 `AssistantPanel.tsx` — 思考强度选择器
- 主组件从 `fetchedModels` 查找当前 `selectedModel` 的 `capabilities`
- 传 `disabled={!capabilities?.thinking}` 给 `ComposerDropdown`
- `ComposerDropdown` 组件：disabled 时按钮加 `composer-control--disabled` 类，`pointer-events: none`，title 显示"该模型不支持思考"
- 当当前选中的 thinking 级别不在 `capabilities.thinkingLevels` 里时，自动回退到 `none`

### 8. CSS `AssistantPanel.css`
新增禁用样式：
```css
.composer-control--disabled {
  opacity: 0.4;
  pointer-events: none;
  cursor: not-allowed;
}
```

### 9. 别名处理
别名模型（sonnet/opus/haiku）capabilities 按"指向最新版"处理：sonnet→sonnet46 能力，opus→opus46 能力，haiku→haiku45 能力。自定义输入的未知模型默认 `thinking: false`（保守），图标用 Cpu fallback。
